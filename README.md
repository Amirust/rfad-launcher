# RFAD Launcher
#### By Amirust

### Что это?
Это реворк лаунчера для скайрим сборки Requiem For A Dream, сделанный на Tauri.<br>
Этот реворк был сделан из-за того что лаунчер, который был сделан на питоне, имел посредственный дизайн (по моим меркам), и жрал по 300 МБайт озу в простое.<br>
По этому я решил переписать его на раст и таури

### Билд

Чтоб собрать сие творение вам нужен Rust, Cargo и Bun.sh/Node.js (желательно последней версии).<br>
Для сборки вам нужно написать `npm tauri build` в консоль (или `bun tauri build` если вы юзаете бан, рекомендую юзать именно бан) <br>
Собранный екзешник будет в папке `target/release/rfad-launcher.exe`<br>

### Google Drive ключ сервис-аккаунта

JSON-ключ **вшивается на этапе компиляции** и в репозиторий не коммитится, без него сборка упадёт с ошибкой `RFAD_GDRIVE_SA_KEY is not set`.

#### Куда вставить

1. Скопируй `src-tauri/.cargo/config.toml.example` в `src-tauri/.cargo/config.toml`.
2. Вставь **весь** скачанный JSON между `'''`:
    ```toml
    [env]
    RFAD_GDRIVE_SA_KEY = '''
    { ...весь service_account.json... }
    '''
    ```

### Релиз и подпись обновлений

Лаунчер не запускает обновление, пока не проверит подпись (minisign, ключ `tauri signer`). Публичный ключ вшит в бинарник: `src-tauri/keys/update.pub`.

#### Как лаунчер проверяет обновление

1. Скачивает `lversions.json` и `lversions.json.sig` из ветки `main` и проверяет подпись манифеста.
2. Версия из манифеста должна быть **строго больше** текущей (semver), чтобы нельзя было откатить пользователей на старую подписанную версию.
3. `downloadUrl` принимается только с `https://github.com/Amirust/rfad-launcher/releases/download/`.
4. Exe скачивается во временный `rfad-launcher.new`. Затем проверяются его подпись (`rfad-launcher.exe.sig`) и SHA-256 из манифеста.
5. Старый exe заменяется новым только после того, как прошли все проверки. Если любая проверка не прошла, лаунчер не обновляется, а причина пишется в `log.txt`.

#### Как выпустить новую версию

1. Подними версию в `src-tauri/tauri.conf.json` **и** `src-tauri/Cargo.toml`. Они должны совпадать.
2. Запусти:
    ```sh
    ./deploy.sh
    ```
    Скрипт проверит пароль ключа, прогонит тесты, соберёт exe (`tauri build --no-bundle`) и всё подпишет. Файлы появятся в `deploy/`:
    - `rfad-launcher.exe`
    - `rfad-launcher.exe.sig`
    - `lversions.json` (поля `version`, `downloadUrl`, `sha256`)
    - `lversions.json.sig`

    `lversions.json` и `lversions.json.sig` также копируются в корень репозитория.
3. Создай GitHub-релиз с тегом `vX.Y.Z` и загрузи в него `rfad-launcher.exe` и `rfad-launcher.exe.sig`.
4. **Только после этого** закоммить и запушь `lversions.json` и `lversions.json.sig` в `main`.

Если поменять порядок шагов 3 и 4, лаунчеры получат 404 и в этот раз просто не обновятся. Ничего не сломается.

Не редактируй `lversions.json` вручную после подписи: подпись покрывает его байты целиком.

Параметры скрипта:
- `SIGN_KEY`: путь к приватному ключу (по умолчанию `./private.key`)
- `SIGN_KEY_PASSWORD`: пароль ключа. Если не задан, скрипт спросит его (Enter = без пароля)

#### Ключ подписи

- `private.key` лежит в `.gitignore`. **Никогда не коммить его** и не клади в GitHub Secrets/CI.
- Держи резервную копию вне репозитория. Если ключ потерян, уже установленные лаунчеры **больше не примут ни одного обновления**.
- Если ключ скомпрометирован, сгенерируй новый (`bun tauri signer generate -w private.key`), положи `.pub` в `src-tauri/keys/update.pub` и выпусти релиз. Пользователям придётся один раз скачать лаунчер вручную.
